#+TITLE: yomitan.el — Yomitan dictionaries in Emacs
#+OPTIONS: toc:nil

Lookup against [[https://yomitan.wiki][Yomitan]] dictionaries from inside Emacs. Deliberately invoked:
no hover, no idle timer, nothing happens until a key is pressed.

* Why this is tractable

A Yomitan dictionary is a zip of JSON, not a proprietary index. Each
=term_bank_N.json= is an array of entries:

: [expression, reading, definitionTags, rules, score, glossary, sequence, termTags]

Modern entries carry =structured-content= in the glossary — a nested tree of
={tag, data, content}= nodes mimicking HTML. The useful handle is =data.content=,
which labels each node's role:

: ul[sense-groups] > li[sense-group] > span[part-of-speech-info]
:                                   > ol > li[sense] > span[field-info]
:                                                    > ul[glossary] > li
: div[attribution]

Honouring those roles instead of flattening the tree is the whole difference
between an entry and a wall of words. Compare, for 位相:

| flattened        | role-aware                                  |
|------------------+---------------------------------------------|
| nounsuru         | =noun=                                      |
| physics          | =1. [physics] phase (e.g. wave, moon)=      |
| phase (e.g. ...) | =2. [math] topology=                        |
| math             | =3. [linguistics] register=                 |
| topology ...     | =— JMdict=                                  |

* Install

Emacs 29+ (built-in sqlite). Import is Python because pushing 500 MB of JSON
through Emacs would be painful; Emacs only ever queries.

#+begin_src sh
./import.py ~/torrents/jitendex-yomitan.zip
#+end_src

Jitendex: 213 term banks, 424,715 entries, ~25 s, 658 MB on disk. Re-running for
the same dictionary title replaces it, so updates are safe. Several dictionaries
can coexist; each is one row in =dict=.

#+begin_src elisp
(add-to-list 'load-path "~/proj/yomitan")
(autoload 'yomitan-at-point "yomitan" nil t)
(autoload 'yomitan-lookup   "yomitan" nil t)
(global-set-key (kbd "C-c y") #'yomitan-at-point)
#+end_src

* Use

| =C-c y=                | longest match starting at point            |
| =C-c y= with a region  | exactly the selection — one character inside a word |
| =C-u C-c y=            | only the single character after point      |
| =C-c Y=                | prompt, prefilled from the region          |
| =w= in the results    | the same word on Wiktionary, in eww        |
| =C-u w=               | Wiktionary in an external browser          |
| =M-x yomitan-dicts=   | loaded version, priority, what is imported |

In the =*yomitan*= buffer, each entry is followed by its *component characters*,
and =RET= or =mouse-1= on one looks it up — so 黐線 shows 黐 ci1 and 線 sin3
beneath it and either can be followed.

Components are glossed in the language of the entry above them, which is why
位相幾何学 lists い しょう いく なん がく and not wai2 soeng1 gei2 ho4 hok6.
Cantonese and Mandarin count as one group for this (黐 in 黐線 comes from
CC-Canto even though 黐線 matched CC-CEDICT); Japanese is its own.

*Scores are not comparable across dictionaries.* Jitendex carries JMdict
frequency ranks while the others are flat, so ordering by score alone put the
Japanese せん above the Cantonese sin3 for 線. =yomitan-dictionary-priority=
orders dictionaries first, score second; reorder it to taste.

Scanning is longest-first, as Yomitan does it, so point on 位相幾何学の研究
matches 位相幾何学 and not 位相. Lookup hits both expression and reading, so
いそう returns all five homophones.

* Cantonese, from Unihan

No download needed: Debian ships Unihan at =/usr/share/unicode/Unihan_*.txt.bz2=.

#+begin_src sh
./import-unihan.py     # 46,205 characters, ~2 s
#+end_src

Readings are indexed, so =maa1= finds 嗎 嘛 媽 妈 嬤 嬷 么 — lookup by jyutping
works because the jyutping *is* the reading.

Two fields carry the usage signal, and they are not the obvious ones:

- =kJoyoKanji= — everyday Japanese. 会 and 学 have it; 會 and 學 do not.
- =kGradeLevel= — the Hong Kong primary grade by which a pupil should know the
  character. 嗎 and 會 are grade 1.

Together they give what a Japanese dictionary cannot:

: 會 【wui6】
:   1. to assemble, meet together  2. a meeting  3. an organization
:   use: HK primary grade 1 · not jōyō (Japanese uses 会)
:   simplified: 会

*=kIRG_JSource= is not this signal and must not be used as it.* It records that a
character appears in a Japanese national standard, but JIS X 0212/0213 encode
many characters Japanese never uses — 嗎 included. A first pass of this importer
printed "not in the Japanese set" from the IRG sources and said the *opposite* of
the truth for 嗎. IRG data is reported as =encoded in:=, never as usage.

* Cantonese and Mandarin words, from CC-Canto and CC-CEDICT

Unihan covers characters; these cover words. Both are in the CC-CEDICT text
format, not Yomitan format:

: 一世人 一世人 [yi1 shi4 ren2] {jat1 sai3 jan4} /the whole life/for a lifetime/
: TRAD    SIMP   [pinyin]       {jyutping}      /sense/sense/

#+begin_src sh
./fetch-data.sh      # ~7 MB, CC BY-SA, into ./data (gitignored)
./import-cedict.py   # CC-Canto 34,335 + CC-CEDICT 125,188 entries, ~9 s
#+end_src

Plain CC-CEDICT has no jyutping, so the separate =cccedict-canto-readings= file
(105,862 readings) is merged in by (traditional, simplified).

Traditional *and* simplified forms are both indexed, and each entry is indexed
under four readings — full jyutping, full pinyin, and the toneless run-together
forms people actually type. So 一世人, 一世人, =jat1 sai3 jan4=, =ci1sin3= and =jatsaijan= all find their
entry, and 唔知 gives "don't know (spoken)".

Six reading forms per entry, because people type all of them: =ci1 sin3= as the
data has it, =ci1sin3= with tones but no spaces (what a jyutping IME user types),
=cisin= with no tones, and the same three for pinyin. Indexing only the first and
last loses the middle one, which is the most likely query of the three.

Traditional ranks above simplified, since equal score and equal length otherwise
make the choice a coin toss.

*Parse tolerantly.* Requiring the closing =/= of =/sense/sense/= silently drops
8,883 of CC-Canto's 34,335 lines — a quarter of the dictionary — because some
lines omit it and some carry a trailing =# adapted from cc-cedict= comment. The
first version of this importer did exactly that and reported success.

* Wiktionary is the level below this

Searching =wiktionary 嗎= in a browser answers the question and costs a context
switch; Wiktionary is superb for etymology and hopeless as a quick gloss — 嗎 has
seven Etymology sections. So this does the light lookup and hands off: =w= opens
the headword in eww, anchored to the section that matches the entry's language
(=#Chinese= for 黐線, =#Japanese= for 位相幾何学), so the page opens where it is
relevant rather than at the top of a very long article.

Set =yomitan-wiktionary-browser= to =browse-url= to leave Emacs by default, or
=C-u w= to do it once.

* Reloading

After editing, =M-x load-library RET yomitan RET=. The autoload pulls the file in
once, so a running Emacs otherwise keeps the old definitions, and
=M-x yomitan-dicts= reports =yomitan-version= so that can be checked.

Keymap bindings are applied by a =dolist= on every load rather than inside
=defvar-keymap=, which expands to =defvar= and therefore *does not reassign an
already-bound variable*. A keymap defined that way is frozen at whatever the
first load put in it: new keys never appear however often the file is reloaded,
and the symptom is =w is undefined= with no fix short of restarting Emacs.

* Known limits

- *words.hk is not included.* It is the best Cantonese dictionary; its free
  dataset needs a signed agreement rather than a plain download, so it is left to
  whoever wants it. It would import into this same schema.
- *No deinflection.* 食べられなかった will not find 食べる. Yomitan has a rules
  engine for this; the =rules= column is imported (=v5=, =v1=, =adj-i= …) so the
  data is there, but nothing uses it yet. This is the main gap.
- *Rendering is plain text.* The =raw= column holds the original JSON, so a
  renderer using images, pitch-accent graphics and clickable xrefs can be added
  without re-importing.
- The db carries =raw= as well as =plain=, which is most of the 658 MB. Dropping
  it would cut that to well under 100 MB at the cost of that future renderer.

* Possible next

A Yomitan entry is =expression · reading · tags · glossary=, which is a hord quad
with the names changed. So this importer is most of a hord importer — lexical data
as cards. Yomitan also has Cantonese support and CC-Canto/Jyutping dictionaries in
the same format, which would feed the 粵諺 material directly.
